# MoviePilot 刮削残留清理插件

扫描对账式清理媒体库里的**孤立刮削文件**——那些视频早就没了、`.nfo`／图片／字幕还留着的文件。

**先出报告，人工确认后才删。** 不会自动删任何东西。

---

## 为什么做这个插件

MoviePilot 官方有一个「源文件联动清理」（`scrapefileclean`），它的做法是**监控删除事件**：盯着下载目录，源文件一消失，就顺着 `(dev, inode)` 找到硬链接联动清理。

这个思路在"文件是被自己看着删掉的"前提下很有效，但有三个绕不过去的限制：

| 限制 | 后果 |
| --- | --- |
| 只在**删除的那个瞬间**触发 | 文件如果是 qBittorrent 自己删的、被其它插件清的、或者插件当时没运行，就完全捕捉不到 |
| **没有存量处理入口** | 已经堆积多年的失效刮削文件，它永远碰不到 |
| `get_page()` 返回 `None` | **没法先预览再删**，开关一开就是直接删 |

第三条尤其要命：刮削文件删错很难恢复，而它不给你看的机会。

本插件走**相反的路**：

> 不关心文件是怎么没的，只关心**现在这个刮削文件还有没有主**。

因此它能：

- **一次扫出全部存量残留**，不需要等下一次删除事件
- **天然不会误删**——从不删除任何正在被引用的文件
- **先给报告**，你自己决定删哪些
- 删之前还有**五道安全阀**复核

**两个插件可以同时用，互不冲突。**

---

## 它是怎么判断的

对每个刮削文件，按优先级依次判断：

```
R1  命中受保护模式（*.trickplay / theme.* 等）        → 保留
R2  是目录级共享文件（tvshow.nfo / poster.jpg ...）
      └ 目录子树里还有媒体文件                        → 保留
      └ 目录子树已经没有任何媒体文件                   → 残留 ✓
R3  普通刮削文件，同目录有同名媒体文件                 → 保留
R3.5 季集号匹配（视频拼音命名、字幕只写 S01E01 时）    → 保留
R4  通用附属文件（subs.zh.srt / ost.flac）
      └ 目录里有媒体                                 → 保留（无法确定归属时不删）
      └ 目录里没有媒体                               → 残留 ✓
R5  其余（同目录找不到对应媒体）                       → 残留 ✓
```

### 目录级共享文件是重点

这是与常见实现差异最大的地方。以剧集为例：

```
/媒体库/剧名 (2020)/          ← tvshow.nfo / poster.jpg / fanart.jpg 属于"这部剧"
    Season 01/                ← season.nfo / season01-poster.jpg 属于"这一季"
        Show.S01E01.mkv
        Show.S01E01.nfo       ← 属于"这一集"
        Show.S01E01.chs.srt
```

`tvshow.nfo` 不是"某集的附属文件"，它代表整个剧集。所以判断它该不该删，要看**这个目录树里还有没有视频**，而不是看有没有同名的视频文件。

很多清理工具在这里会误删：一部剧只剩 `S01E05` 了，它们看到 `tvshow.nfo` 找不到同名视频，就把整部剧的元数据删了。本插件的规则是——**只要目录里还有任何一个视频，`tvshow.nfo` 就不动**。

### 多版本共存

```
电影H (2015)/H.1080p.mkv
电影H (2015)/H.2160p.mkv
电影H (2015)/H.1080p.nfo     ← 保留（对应 1080p）
电影H (2015)/H.2160p.nfo     ← 保留（对应 2160p）
电影H (2015)/poster.jpg       ← 保留（目录级，目录里有视频）
```

### 通用名文件

`subs.zh.srt`、`chinese.srt` 这种不带片名的字幕：

- 目录里**只有一个**视频 → 认为属于它，保留
- 目录里有**多个**视频 → 说不清归属，**保留**（宁可漏删，不可错删）
- 目录里**没有**视频 → 残留，清理

### 季集号兜底（重要）

国内剧集极常见的命名错位：

```
Chen.Mo.De.Zhen.Xiang.S01E01.mkv    ← 视频用拼音
S01E01.chs.srt                       ← 字幕只写季集号，名字完全对不上
```

纯按文件名匹配会把这份**正常字幕**判成残留。所以增加了季集号兜底：只要刮削文件里能提取到 `SxxExx`（或 `第N集`、`1x01`、`EP01`），而同目录存在**相同季集号**的视频，就认为有主。

边界是严格的：

| 情况 | 结果 |
| --- | --- |
| 字幕 `S02E03`，目录有 `S02E01` 的视频 | **残留**（不能跨集认领） |
| 字幕 `S01E01`，目录只有 `S02E01` 的视频 | **残留**（季号必须对齐） |
| 字幕 `S01E01`，目录有 `剧名.S01E01.mkv` | 保留 |
| 字幕 `第01集`，目录有 `剧名第01集.mkv` | 保留 |

## 五、六道安全阀

判断和执行是分开的。`analyzer.py` 只判断，`deleter.py` 只执行，执行前逐条复核：

| 阀 | 规则 | 防的是什么 |
| --- | --- | --- |
| V1 | 路径必须落在配置的媒体库根目录内 | 目录穿越、配置写错 |
| V2 | 路径必须在**本次扫描**的残留清单里 | 报告过期后目录结构已变 |
| V3 | 路径必须仍是刮削文件后缀 | 扫描后被换成了视频文件 |
| V4 | 路径不能命中排除关键字 | 用户明确排除的区域 |
| V5 | 符号链接不处理 | 删链接语义混乱，交给人 |
| V6 | 文件被其它程序占用则跳过 | qBittorrent 做种/校验、播放器读取、同步盘写入 |

**任何一条不过，拒绝删除并记录原因。** 就算前端传来的路径被篡改，也删不掉库里的正常文件。

### V6 的平台限制（重要）

这条保护**只在 Windows 上真正有效**：

| 平台 | 有效性 | 说明 |
| --- | --- | --- |
| Windows | ✅ 有效 | 删除/改名被占用文件返回 `WinError 32`，信号可靠 |
| Linux / macOS | ❌ 基本无效 | 被打开的文件照样能 unlink/rename，系统层没有共享冲突概念 |
| SMB / NFS / NAS | ⚠️ 视服务端 | 可能误判成「无法判断」而全部跳过 |

> **实现说明（别改回去）**：检测占用**不能**用 `open()` 或 `os.open(O_RDWR)` 试探——
> Windows 上 Python 用共享模式打开，文件被独占占用时这两种方式**都能成功打开**，
> 是彻底的假阴性。只有删除/改名这类「命名空间操作」才具备区分能力。
> 代码里就有针对这一点的对照测试，防止后人「优化」回错误写法。

如果在 NAS 上发现「所有文件都被跳过」，请关闭「跳过被占用文件」开关。

## 安装

### 方式一：作为插件市场仓库

1. 把本仓库推到 GitHub（公开仓库）
2. MoviePilot 里添加插件市场地址：
   `PLUGIN_MARKET` = `https://github.com/<你的用户名>/MoviePilot-Plugins`
3. 插件市场搜索「刮削残留清理」安装

### 方式二：本地联调（推荐先这么试）

```bash
# 把插件目录放进运行目录
cp -r plugins.v3/scrapecleaner /path/to/moviepilot/plugins.v3/
# 或者用本地仓库路径
PLUGIN_LOCAL_REPO_PATHS=/path/to/MoviePilot-Plugins
PLUGIN_AUTO_RELOAD=true
DEBUG=true
```

重启 MoviePilot，在「插件」里找到「刮削残留清理」。

## 配置

### 媒体库目录

每行一个，填**容器内**的路径：

```
/media/电影
/media/剧集
```

插件会递归扫描。建议直接填库根目录，不要填单个影片文件夹。

### 删除方式

- **移入回收站（推荐）**：移动到回收目录并保留原有层级，删错了能捞回来
- **直接删除**：不可恢复

回收目录**必须位于媒体库之外**。如果配在库内，插件会拒绝执行——否则下次扫描会把回收站里的文件再判一次。

默认回收目录是插件数据目录下的 `recycle`。

### 定时扫描（cron）

5 段 cron，例如 `0 4 * * *` 表示每天 4 点。

**定时扫描只出报告和通知，不会自动删除。** 删除永远需要你手动确认。留空则不定期扫描。

### 排除关键字

路径包含任一关键字就跳过，每行一个。适合排除 `@eaDir`、`#recycle` 这类系统目录（内置已默认跳过一部分）。

### 新文件保护期

修改时间在保护期内的文件不判残留。**默认 1440 分钟（1 天）**。

防的是「刚整理完，刮削文件写好了但视频还在转移中」这种瞬间状态。库里已有的老文件不受影响，所以这个默认值不会降低清理效果。

### 跳过被占用文件

默认开启。详见上文「V6 的平台限制」。

### 联动清理转移记录

开启后，删完刮削文件会顺带清理指向这些文件的失效转移记录。

两条保护：
- 目标文件**或源文件**还在的记录，不删（说明不是真的失效）；
- 属于**转移任务**的记录，宿主自己会保护，插件删不掉也不会报错（删完会复查，确认真的删了才计入）。

### 自定义规则（正则）

一般不用填，用于小众命名规范：

| 配置 | 作用 |
| --- | --- |
| 额外媒体后缀 | 额外视为「视频」的后缀，如 `.rmvb7` |
| 媒体文件名正则 | 匹配到的文件视为媒体 |
| 刮削文件名正则 | 匹配到的文件视为刮削文件 |
| 目录级文件名正则 | 匹配文件名主干，视为整个目录的共享文件 |

**写错不会让插件崩溃**——非法正则会被记进扫描报告的「错误」里并忽略。另有正则长度上限，防止误粘长文本触发正则回溯把宿主卡死。

### 多媒体库分别配置策略（高级）

不同库可以有不同策略。每行一条，用 `|` 分段：

```
/media/movies | mode=recycle | keep_days=60 | exclude=样品,预告
/media/tv | mode=remove
/media/readonly | disabled=true
/media/tv/纪录片 | disabled=true
```

可用键：

| 键 | 值 | 说明 |
| --- | --- | --- |
| `mode` | `recycle` / `remove` | 该库的删除方式 |
| `recycle_dir` | 路径 | 该库单独的回收目录 |
| `keep_days` | 整数 | 回收站保留天数 |
| `disabled` | `true` / `false` | 整个库完全不处理 |
| `min_age_minutes` | 整数 | 该库单独的保护期 |
| `exclude` | 逗号分隔 | 该库额外的排除关键字 |
| `max_files` | 整数 | 该库的单次扫描上限 |

规则：**最长路径前缀优先**；没命中的走全局设置；以 `#` 开头是注释。

写错的键或值会被忽略并在日志里提示，绝不影响其它规则。可以用 `GET /api/v1/plugin/ScrapeCleaner/rules` 查看实际生效的策略和警告。

## 使用流程

1. **配置媒体库目录**，保存并启用
2. 进插件详情页，点**「立即扫描」**
3. 看报告：共找到多少残留、都在哪些目录
4. 三种删除方式，按精细程度递增：

   | 方式 | 粒度 | 适用 |
   | --- | --- | --- |
   | 「清理全部」按钮 | 全部 | 你已经确认这批都该删 |
   | 「清理本组」按钮 | 单个目录 | 想按目录分批处理 |
   | 配置页「精细清理」文本域 | 任意挑选 | 想逐条挑选，删掉不想动的行 |

5. 清理完成后看历史记录

### 关于「精细清理」

MoviePilot V3 的详情页（`get_page()`）渲染器**不支持数据绑定**——没有 `model`，复选框勾选状态无法维护，而且每次 API 调用后整页重绘、勾选必然丢失。这是宿主架构限制，不是本插件偷懒。

所以真正能"逐条挑选"的入口放在**配置页**：那里 `model` 是真正的双向绑定。

点「载入上次扫描的残留清单」→ 路径灌进文本域 → **删掉你不想删的行** → 点「执行清理」。

这个文本域不进入持久化配置，用什么改什么。

### 导出报告

把扫描结果导出成表格，方便在 Excel 里筛选或存档：

```
GET /api/v1/plugin/ScrapeCleaner/export?fmt=csv    # Excel 直接打开
GET /api/v1/plugin/ScrapeCleaner/export?fmt=json   # 程序处理
```

CSV 用 **UTF-8 with BOM** 编码，中文版 Excel 双击打开不会乱码。列包括：完整路径、文件名、所在目录、是否残留、判定理由、判定依据、是否目录级文件、大小。

### 查看生效策略

```
GET /api/v1/plugin/ScrapeCleaner/rules
```

返回实际生效的多库策略和解析警告——配置多库策略后建议先看这个确认写对了。

## API 一览

所有路由都需要登录态（`auth: bear`）。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/scan` | 扫描媒体库，返回报告 |
| GET | `/report` | 上次扫描报告（无则返回空结构） |
| POST | `/delete` | 删除指定路径（body: `{"paths": [...]}`） |
| GET | `/history` | 清理历史 |
| GET | `/export?fmt=csv\|json` | 导出报告（文件下载） |
| GET | `/rules` | 生效的多库策略与警告 |

远程命令：`/scrapecleaner_scan` —— 在聊天里触发一次扫描。

## 撤销删除

如果用了回收站模式：

```
<插件数据目录>/recycle/<时间戳>/<库名>/<原相对路径>
```

保留天数可配（默认 30 天，0 = 永久）。过期批次在定时扫描后自动清理。

要手动恢复，直接把文件挪回原位即可。

## 开发

### 目录结构

```
MoviePilot-Plugins/
├── plugins.v3/scrapecleaner/
│   ├── __init__.py        # MoviePilot 集成层：配置、API、页面、定时任务
│   ├── analyzer.py        # 纯判断：扫描对账（不依赖 MoviePilot）
│   ├── deleter.py         # 纯执行：六道安全阀（不依赖 MoviePilot）
│   ├── history.py         # 纯逻辑：转移记录失效判断
│   ├── library_rules.py   # 纯逻辑：多库策略解析
│   ├── exporter.py        # 纯逻辑：CSV/JSON 导出
│   └── host_adapter.py    # 宿主适配：把纯逻辑接到 MoviePilot 能力上
├── tests/v3/scrapecleaner/    # 12 个测试套件
├── icons/clean.png
└── package.v3.json
```

**分层原则**：除 `__init__.py` 和 `host_adapter.py` 外，其余模块都**不依赖 MoviePilot**。清理类插件删错的代价太高，核心逻辑必须能被穷举验证——所以它们可以在没有宿主环境的机器上直接跑测试。

`host_adapter.py` 集中处理宿主 API 的坑（惰性导入、方法差异、静默失败），避免这些细节污染判断逻辑。

## 已知限制

- **不清理种子**。删除种子风险高，官方「下载器助手」做这件事更合适。
- **不处理硬链接联动**。文件被删了就是被删了，本插件只看当前状态。
- **单线程扫描**。超大库（几十万文件）会慢，可以用 `max_files` 限制单次扫描量。
- **勾选式多选做不了**。见上文「关于精细清理」，这是 V3 渲染器限制。
- **V6 占用检测在 Linux 上无效**。见上文「V6 的平台限制」。
